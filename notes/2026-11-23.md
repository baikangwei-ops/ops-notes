**19:10 找不到 Git Bash**

按 Win 键搜 `git bash`，只出一堆网页搜索结果，没有本地程序。

但 `where git` 能定位到：

```
D:\LenovoSoftstore\Install\WorkBuddy\resources\vendor\PortableGit\mingw64\bin\git.exe
```

说明 git 是有的，只是某个软件自带的便携版——解压即用，没走过安装流程，所以不注册开始菜单快捷方式。暂时没折腾安装，先用 PowerShell 自带的 ssh 顶着。**明天得装个 Git for Windows**，不然以后没有 git bash 用。

**19:15 生成密钥，第一次静默失败**

执行 `ssh-keygen` 之后没报错，但 `cat ~/.ssh/id_ed25519.pub` 提示 No such file or directory。

原因是 `~/.ssh` 这个目录本来就不存在，ssh-keygen 又不会自动创建，写文件失败也没明显提示。加上 `mkdir -p ~/.ssh` 之后就正常了。

这个坑挺典型：Linux 的工具失败经常不出声，退出码也是 0，得自己 `ls` 一下确认文件到底生成没有。

公钥拿到后贴到 GitHub：Settings → SSH and GPG keys → New SSH key，标题随便写了个 `my-pc`。

**19:22 报 Host key verification failed**

`ssh -T git@github.com` 直接报这条，连 yes/no 的询问都没出现。

查了下是 known_hosts 的机制：SSH 第一次连陌生主机，要把对方的主机公钥指纹存到 `known_hosts` 里，以后每次连都比对，防止中间人劫持。第一次必须人回答 yes 才写入，非交互的终端没法回答，就直接判失败。

在我自己的 PowerShell 窗口里手动敲了 `yes` 才过去。

**19:25 22 端口超时（今天最大的坑）**

密钥验证过了，但换个窗口再连，`ssh -T git@github.com` 直接卡住，一分钟多后 `Connection timed out`。

同时 `curl github.com` 是通的，说明网没断，问题出在端口上。GitHub 官方文档提到 SSH 有备用通道，试了一下：

```
ssh -T -p 443 git@ssh.github.com
```

立刻返回 `Hi baikangwei-ops! You've successfully authenticated`。确认是 22 端口被链路掐了。

然后想把配置固化到 `~/.ssh/config`：

```
Host github.com
  HostName ssh.github.com
  Port 443
```

意思是：我连 github.com 这个名字的时候，实际去连 ssh.github.com 的 443。这样 git clone/push 都不用改地址。

**结果没生效。** 又折腾了一会儿才发现：记事本保存的时候自动给文件名加了个 `.txt`，文件实际叫 `config.txt`，ssh 根本不读这个文件。改成 `config` 才好了。

**19:35 建仓库报了错，其实已经建好了**

点 Create repository 弹出红色 `Something went wrong!`。

刷新重来，提示 `ops-notes already exists in this account`。才反应过来——第一次其实建成功了，只是服务器返回的响应在路上丢了，页面显示成失败。

这算是「超时不等于失败」的现场版。以后再碰到类似报错，先去看结果状态，别急着重复提交。

**19:45 目录建错了**

想在仓库里建 `notes/README.md`，结果建出来是 `操作说明/注释/README.md`。

GitHub 网页的文件名输入框支持用 `/` 直接新建目录（输 `notes/` 就建 notes 文件夹），这个设计挺好用，但当时用的是中文输入法，输进去的字和斜杠全被当成目录名了。

删掉重建，切英文输入法，输入框里打 `notes/README.md`，看到上面面包屑变成 `仓库名 / notes /` 才敢提交。

**20:20 整理笔记**

把今天的过程写进 `notes/` 提交上去。第一次 push 报了 `Connection reset by peer`，重试一次变成 `Everything up-to-date`——又是同一个情况，第一次其实已经推上去了，只是响应被重置。

## 8 个问题，按现象记

1. **开始菜单搜不到 Git Bash** → 只有便携版 git，不注册快捷方式。安装 Git for Windows 解决。
2. **ssh-keygen 静默失败** → `~/.ssh` 目录不存在。先 `mkdir -p ~/.ssh`。
3. **Host key verification failed** → 首次连接要人工信任主机指纹。手动敲 yes，或 `ssh-keyscan >> known_hosts`。
4. **22 端口超时** → 链路阻断。改走 `ssh.github.com:443`，写进 `~/.ssh/config`。
5. **config 写了不生效** → 记事本存成了 `config.txt`。改名成无后缀的 `config`。
6. **建仓库报错但已成功** → 响应丢失，服务端其实写库了。先去列表确认，别重复提交。
7. **中文用户名 URL 乱码** → URL 只允许 ASCII。改成英文。
8. **建出中文目录** → 中文输入法把字和斜杠当成了目录名。切英文输入法。

## 今天弄明白的概念

**公钥和私钥**：一对钥匙，公钥交给 GitHub（相当于给它一把锁），私钥留在我电脑里。以后登录时它拿公钥验证我手里的私钥，对得上就放行。私钥不能外传，公钥随便给。

**known_hosts 和 authorized_keys 不是一回事**：known_hosts 里存的是「我信任哪些服务器」，authorized_keys 里存的是「哪些用户公钥可以登录我」。前者防对面是假服务器（中间人），后者防别人冒充我登录。

**超时和拒绝的区别**：`Connection refused` 说明对方活着但端口没开；`Connection timed out` 说明包发出去根本没回音，一般是链路被防火墙 DROP 了。两种情况的排查方向完全不一样。

**幂等**：同一个请求执行一次和执行十次，结果一样。今天建仓库那次就是反例——因为不确定成没成功，多提交了一次，被提示「已存在」。以后写批量脚本，一定要先查状态再决定做不做。

**URL 编码**：「白」字的 UTF-8 是 `E7 99 BD`，在 URL 里必须写成 `%E7%99%BD`。日常遇到的中文乱码，基本都是某一层用了错误的编码。

**PATH**：敲一个命令时，系统按 PATH 这个列表里的目录顺序去找同名 exe。有 exe 但不在 PATH 里，就只能写全路径调用。
