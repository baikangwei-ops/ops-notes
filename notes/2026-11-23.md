# 2026-11-23 · D1

补全计划第一天，任务是把 GitHub 搭起来，当后面 99 天所有产出的存放地。本来以为注册个号、配个密钥、建个仓库，半小时的事，结果弄了两个多小时，中间卡了八次。一次比一次离谱，记下来。

最先栽的是用户名。我填的是「白夜-2004」，填完才反应过来这个名字以后要写进简历、贴在仓库链接里——中文在 URL 里会被转义成一长串 `%E7%99%BD%E5%A4%9C`，别人看着一头雾水。改成 `baikangwei-ops` 才算完。这事让我第一次碰到 URL 编码：中文字符在网址里必须先转成 UTF-8 字节再一个个 `%` 转义，平时看到的中文乱码基本都是某一层用错了编码。

然后开始找 Git Bash。按 Win 键搜 `git bash`，跳出来全是网页搜索结果，没有本地程序。但 `where git` 又能定位到一个路径，在 WorkBuddy 自带的 PortableGit 目录里——说明 git 是有的，只是某个软件附带的便携版，解压即用没走过安装流程，自然不往开始菜单注册快捷方式。今天先用 PowerShell 自带的 ssh 顶着，回头得装个正式的 Git for Windows。

配密钥时踩了个特别阴的坑。执行 `ssh-keygen`，没报错，可 `cat ~/.ssh/id_ed25519.pub` 提示文件不存在。卡了一下才想到：`~/.ssh` 这个目录本来就不存在，ssh-keygen 不会自动建目录，写文件失败也没给出明显提示。补了 `mkdir -p ~/.ssh` 再执行就正常了。这是今天学到的第一条硬规矩：**Linux 的命令失败经常不出声，退出码还是 0，得自己 `ls` 一下确认文件到底在不在**。

公钥贴到 GitHub 之后，测试连接报 `Host key verification failed`，连 yes/no 的询问都没弹。查了才知道这是 known_hosts 的机制：SSH 第一次连一个陌生主机，得把对方的主机公钥指纹记下来，以后每次连都比对，防的是中间人冒充服务器。第一次必须有人回答 yes 才会写入，我这是在非交互终端里敲的，没人回答，就直接判失败。后来在自己的 PowerShell 窗口里手动敲了 yes 才过去。顺便理清了一组老混淆的概念：known_hosts 存的是「我信任哪些服务器」，authorized_keys 存的是「哪些公钥可以登录我」——一个防对面是假服务器，一个防别人冒充我登录，完全两码事。

今天最大的坑是 22 端口。密钥验证过了，换个窗口再连 `ssh -T git@github.com`，直接卡住，一分多钟后 `Connection timed out`。同时 `curl github.com` 是通的，说明网没断，问题就出在端口上。想起 GitHub 官方有个 SSH 备用通道，试了 `ssh -T -p 443 git@ssh.github.com`，秒回 `Hi baikangwei-ops! You've successfully authenticated`——果然是 22 端口在这条链路上被掐了。这里把超时和拒绝分清楚了：`Connection refused` 是对方活着但端口没开，`Connection timed out` 是包发出去根本没回音、一般被防火墙 DROP 了，两者排查方向完全不同。

想把 443 通道固化下来，写进 `~/.ssh/config`：

```
Host github.com
  HostName ssh.github.com
  Port 443
```

意思是连 github.com 这个名字时实际去连 ssh.github.com 的 443，这样 git clone/push 都不用改地址。结果写完没生效，又折腾一阵才发现——我用记事本保存，它偷偷给文件名加了个 `.txt`，文件实际叫 `config.txt`，ssh 根本不读。改成无后缀的 `config` 就好了。这种坑最气人，命令写对了、地址也对，输在一个看不见的后缀上。

建仓库时也闹了个乌龙。点 Create repository 弹出红色 `Something went wrong!`，我以为没建成，刷新重来，结果提示 `ops-notes already exists in this account`——第一次其实成功了，只是服务器的响应在路上丢了，页面显示成失败。这就是超时不等于失败的现场版：以后碰到这种报错，先去列表看一眼到底成没成，别急着重复提交。顺带记下一个词叫幂等——同一个请求执行一次和执行十次结果一样，写批量脚本时尤其要先查状态再决定做不做。

目录也建错过一次。想在仓库里建 `notes/README.md`，网页的文件名输入框本来就支持用 `/` 直接新建目录（打 `notes/` 就建文件夹），但当时开着中文输入法，输进去的字连同斜杠全被当成了一个目录名，建出来是 `操作说明/注释/README.md`。删掉重建，切英文输入法，看着面包屑变成 `仓库名 / notes /` 才敢提交。

最后把今天的过程写进 `notes/` 推上去，第一次 push 又报 `Connection reset by peer`，重试一次变成 `Everything up-to-date`——和建仓库那次一模一样，第一次其实推上去了，只是响应被重置。一天里被"响应丢失"坑了两次，算是记住了。

今天真正弄懂的东西，其实都是从这些坑里长出来的：一对钥匙里公钥交给 GitHub、私钥留在自己电脑；超时和拒绝是两类问题；URL 只认 ASCII；还有一个之前没想过的 PATH——敲命令时系统按 PATH 列表里的目录顺序找同名 exe，有 exe 不在 PATH 里就只能写全路径。这解释了为什么便携版 git 明明在硬盘上，我却"找不到"它。

欠着的：还没装正式的 Git，config 里没写 IdentityFile 靠默认路径找密钥，本地仓库放哪也没定，还有 `git add/commit/push` 今天是照着敲的，暂存区到底干什么还没真明白。明天接着弄。
