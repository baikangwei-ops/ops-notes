前面三天都在自己电脑上折腾 git，今天终于碰到“云”了。19:30 打开计划，D4 只有四行字：实名认证、起一台 2C2G 的 ECS、安全组只放行 22、ssh 登录。我以为半小时能收工，结果中间自己把服务器关机了，又学了一课。

今晚做完的实际成果：**从零到一台能 ssh 登录的阿里云 ECS 实例**，中间踩了一个坑（C007），也第一次看清“本地虚拟机和云服务器到底差在哪”。

## 今日新掌握的命令

**远程与勘察**

| 命令 | 干什么 | 关键点 | 要不要背 |
|---|---|---|---|
| `ssh root@公网IP` | 用 ssh 远程登录服务器 | 不写端口就是默认 22；首次连接要输 `yes` 信任主机指纹（known_hosts 机制） | **必背**，天天用 |
| `hostname` | 查当前主机名 | 登错机器的第一道保险；脚本里取值也靠它 | **必背** |
| `uname -r` | 只查内核版本 | `3.10.0-1160.el7.x86_64`：内核版本/补丁号/发行版体系/架构 | **必背** |
| `cat /etc/redhat-release` | 查发行版版本 | 和 `uname -r` 不是一回事：一个内核版本，一个发行版版本 | **必背** |
| `lsblk` | 列出所有块设备、分区、挂载点 | 只读，比 `fdisk -l` 安全；**云盘叫 vda，本地虚拟机叫 sda** | **必背** |
| `free -h` | 查内存使用 | `-h` 是人类可读单位；**看 available 那一列，不看 free**；buff/cache 可回收 | **必背** |

**开关机与主机名（今晚翻车的地方）**

| 命令 | 干什么 | 关键点 |
|---|---|---|
| `poweroff` | 关机 | 机器会停住，**云上不会自己回来**，必须回控制台点启动 |
| `shutdown -h now` | 关机（另一种写法） | 同上 |
| `reboot` | 重启 | 想继续用就用它，掉线一分钟自己回来 |
| `init 0` | 关机（老写法） | 认得出就行 |
| `hostnamectl set-hostname 新名字` | 改主机名 | 改完重启生效，重启后依然保留 |

> 今天的命令表里有一半是“查信息”的。查信息看起来没技术含量，但运维事故一半起于“没确认现状就动手”——勘察四连（hostname → uname -r → lsblk → free -h）以后就是我拿到任何一台新机器的开场动作。

## 19:30 领机器：比装 VMware 快十倍

阿里云注册 + 支付宝扫码实名，两分钟过审。然后进试用中心，有两个选择：云服务器 ECS（300 元额度，3 个月）和轻量应用服务器（1 个月，1G 内存）。

选了 **ECS 个人版**。理由想清楚了才点：轻量服务器是“建站套餐”，预装宝塔面板、WordPress，**面板会把底层操作全包住**，我练的就是底层，不能用它。ECS 才是真控制台。

规格页里有一列价格，我一开始想选配置高的，后来看明白一件事：**额度是固定的 300 元，单价越低能用的时间越长**。

- 2核2G 经济型 e：¥0.123/小时 → 约 2439 小时
- 最高的那档：¥0.731/小时 → 只剩 410 小时

同样 300 元，差 6 倍使用时长。这个“用额度换时长”的思路，和买流量套餐是一个道理。最后选：**北京地域（离郑州最近）+ 2核2G + 40G ESSD + CentOS 7.9**（和班级环境一致，白天学什么晚上原样复现）。

预装应用那栏四个（宝塔/WordPress/Docker/LNMP）**一个都没勾**——学习机要干净裸机，装什么以后自己手动装才有学习价值。

创建完弹了一个“ECS 专属安全防护权益限时领取”，主机病毒防护 + 云备份。想了想都关了：云备份会代替我练快照（D5 的课），病毒防护会在 2G 内存的机器上常驻一个 agent 添乱。**学习机只装自己手动装的软件**——这条以后也适用于生产环境判断。

## 19:45 安全组：云和本地最大的一个区别

本地 VMware 装完系统，ssh 直接就能连。云上不是——**默认所有端口都关着**，门要自己开。

在安全组里加规则，纠结了一个字段：协议选“所有 TCP”还是“自定义 TCP”。最后改成后者 + 端口 `22/22`，理由是想明白了一条原则：

> **最小开放原则**：需要哪个端口开哪个。公网上有扫描器 24 小时扫全网，新开的 IP 几分钟就会被扫到。“所有 TCP + 全部端口”等于把机器所有门朝外敞开。

配置清单：允许 / 自定义 TCP / 22/22 / 源 0.0.0.0/0 / 描述“ssh 远程登录”。描述栏认真写，以后端口多了，这张规则表就是这台机器的端口台账。

## 20:00 登进去，然后自己把机器关了

`ssh root@112.126.89.92` → 首次连接弹主机指纹确认，敲 `yes`（D1 学的 known_hosts，第三次见面）→ 输密码，**屏幕上没有任何回显**（连星号都没有），盲打完回车，进去了。

提示符从 `白康伟@bai8237`（我自己的电脑）变成 `[root@iZ2ze... ~]#`（北京机房那台服务器）。那一刻挺奇妙的：人在郑州，敲的命令跑在北京的机器上——这就是“云”的全部含义。

然后我按 Linux 的老习惯改主机名，改完想验证效果。**结果我用的是 `poweroff`，不是 `reboot`。**

机器直接关机了，终端“卡死”在那里不动。我以为是终端坏了，关掉重开，ssh 报：

```
ssh: connect to host 112.126.89.92 port 22: Connection timed out
```

第一反应是安全组配错了（毕竟刚学超时=端口不通）。查了一圈规则都是对的，最后回控制台一看——**实例状态：已停止**。

原来“卡死”不是故障：终端还开着，但对面的机器已经没了。本地 VMware 关机后窗口还在，点一下“开启此虚拟机”就活了，所以从来没觉得 `poweroff` 有风险；**云上没有那个窗口兜底**，机器停了就是停了，必须回控制台手动启动。

这个坑进了 [故障案例库 C007](故障案例库.md)，和 C001 正好组成“超时排查”的上下篇：C001 是超时=链路被掐，C007 是超时=目标根本不在线。

## 20:20 恢复后跑勘察四连

控制台点“启动”，等状态变回运行中，再 ssh——进去了，`hostname` 显示我改的新名字（说明改主机名重启生效这个习惯本身没错，错的只是关机方式）。

四个命令 + 一个补充：

```
hostname                 # 新主机名，生效了
uname -r                 # 3.10.0-1160.el7.x86_64 → 内核 3.10，el7 体系，64 位
cat /etc/redhat-release  # CentOS Linux release 7.9.2009
lsblk                    # vda 40G，vda1 挂 /
free -h                  # total 1.8G，Swap 0B
```

三个和本地不一样的地方，全记下来了：

1. **盘叫 vda 不叫 sda**：v = virtio（云/虚拟化专用高速通道），s = SCSI（模拟传统硬盘）。同一个 `lsblk`，两种命名暴露了底层虚拟化技术的不同
2. **2G 内存显示 1.8G**：内核和硬件预留吃掉一点，正常现象，不是被坑
3. **Swap 是 0B**：云镜像默认不开 swap。这意味着内存一满就直接触发 OOM Killer，没有 swap 缓冲——D2 口述的 swap 和 OOM Killer，在这台机器上是“没有安全垫”的版本

顺便把 `free` 的输出读懂了：`free` 那一列很小不代表内存不足，内核会主动拿空闲内存做磁盘缓存（buff/cache），**真正能用的看 `available`**。“free 只剩 100M 是不是要爆了”是面试高频陷阱题，答案就在这一列。

## 今天弄明白的几个概念

**我原以为实例是个新东西，其实它就是云上的虚拟机**：阿里云从机房物理机上切出一块（2核2G+40G），装上系统配个公网 IP，这个“跑起来的独立小服务器”就叫实例。本地 VMware 里的虚拟机、ECS 实例、数据库实例、Redis 实例，共同点都是“从大资源池里切出来、能创建能销毁的一份独立服务”。

**停止 ≠ 释放**：停止只是关机，资源还占着、额度还在扣（0.12 元/小时）；释放才是真删掉。今晚的关机事故让我把这条刻进骨头里了。

**云运维不是“ssh 敲命令”一件事**：今晚做的是主机层（第二层）。完整的云运维有四层——资源层（控制台/API 管 VPC、安全组、SLB、RDS）、主机层（ssh）、可观测层（监控告警）、自动化层（脚本/Ansible/流水线/K8s）。我的计划正好按这个顺序排到 3 月。

**额度思维**：试用给的是钱不是时间，所以选单价最低的规格，用时长换自由度。
