## 2026-11-17 · Day 1 · 内核态与用户态（系统调用）

**一句话**：命令全程在用户态运行，每次需要内核服务的那一瞬间才切进内核态，办完立刻退回。切换的单位是"一次系统调用"，不是"一整条命令"。

### 一、通俗模型：银行柜台

```text
普通客户  = 你的程序（cat / ls / bash 自己也是客户）
后台金库  = 内核（管内存、磁盘、网络、CPU）
柜台窗口  = 系统调用（唯一合法通道，递单子办事）
保安核对  = 权限检查（在窗口处发生，由内核执行）
```

客户永远站在大厅里，一次也没进过后台——**只是不停递单子**。

### 二、一条命令的真实流程

```text
1. 敲 `cat /etc/passwd` → bash 接收（用户态，只做解析：拆参数、查 PATH）
2. bash 发起 syscall fork/exec → 内核创建新进程（切内核态→回用户态）
3. cat 干活，内部反复递单子：
     open()   → 内核检查权限，通过则返回文件句柄
     read()   → 内核从磁盘取数据
     write()  → 内核写到屏幕
4. exit()     → 内核回收进程
```

**修正的误解**：不是"整条命令进入内核态执行"，而是来回切换几百上千次。`strace -c ls` 能看到这个次数。

### 三、三层

**是什么**：内核态=特权模式，能碰硬件和全部内存；用户态=受限模式。程序只能通过系统调用请求内核代劳。

**为什么**（两个理由）：
- 保命：几百个程序若都能直接摸内存和硬盘，一个写坏就全崩
- 管秩序：内存/磁盘/网络要给谁、给多少，必须有个统一的管理者

**延伸到权限**：`cat /etc/shadow` 报 Permission denied，不是 cat 聪明，是内核在 `open()` 入口把单子退回来了。**权限由内核执行，不是文件自我保护。** SUID、粘滞位、chmod 777 仍被拦（SELinux），答案都是这同一句。

**坏了怎么查**：
- 进程卡住、无日志 → `strace -p PID` 看它此刻卡在哪个 syscall
- 某命令慢 → `strace -T 命令` 看每个调用耗时，区分磁盘慢（open/read）、网络慢（connect）、服务慢
- 谁在偷偷执行脚本 → `execsnoop`（eBPF，后面学）

### 四、命令清单

| 命令 | 作用 |
|---|---|
| `strace 命令` | 跟踪该命令的全部系统调用 |
| `strace -p PID` | 挂到运行中的进程上 |
| `strace -T` | 每个调用显示耗时（秒） |
| `strace -c` | 统计：每类调用次数+总耗时 |
| `strace -e trace=open,read` | 只过滤关心的调用 |
| `strace -f` | 跟踪子进程（脚本/多进程必加） |

### 五、10 分钟实验（今天必做）

```bash
# 1. 看一个命令的三步
strace -T -e trace=open,read,write cat /etc/passwd

# 2. 看"一条命令"背后有多少次调用
strace -c ls

# 3. 看权限拒绝发生在哪
strace -e trace=openat cat /etc/shadow    # 普通用户执行，看到 EACCES
```

### 六、自测（能口述即过关）

1. `cat` 一次系统调用都不发生，可能吗？→ 不可能，至少 open/read/write
2. 权限检查发生在流程第几步？→ open() 切进内核的那一瞬间
3. 程序卡住且无日志，第一步做什么？→ strace -p 看它停在哪个调用
4. bash 是内核的一部分吗？→ 不是，它是普通用户态程序，靠 syscall 干活

### 七、连到后面

- **明天（进程/线程）**：进程就是大厅里排队的另一批客户，`fork` 本身就是一次 syscall
- **容器（第 3 个月）**：容器 = 被 namespace 隔离视图、cgroup 限制资源的普通进程，全是内核机制 → 今天这条是它的地基
- **性能（第 1 个月末）**：`strace -T` 把"磁盘慢/网络慢/服务慢"三类问题一次分开
