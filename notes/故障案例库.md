## C001　SSH 连 GitHub 一直超时

**环境**：Windows 10/11 + PowerShell（Windows OpenSSH），目标 `github.com`

**现象**

`ssh -T git@github.com` 无任何输出，卡一分多钟后报：

```
ssh: connect to host github.com port 22: Connection timed out
```

**排查过程**

1. 先怀疑断网 → `curl -I https://github.com` 正常返回 200，排除网络完全不通
2. 怀疑密钥问题 → 但密钥错误会报 `Permission denied (publickey)`，不会超时，排除
3. 判断是端口层面：22 端口连通性被阻断/丢包
4. 查 GitHub 官方文档，确认提供备用 SSH 通道 `ssh.github.com:443`
5. 验证：`ssh -T -p 443 git@ssh.github.com` → 立即返回 `Hi baikangwei-ops!`
6. 结论成立，写进 `~/.ssh/config` 固化

**根因**

GitHub 的 SSH 服务监听 22；部分网络链路对 22 端口做阻断，表现为 SYN 无响应（超时），而不是拒绝。

**修法**

```
# ~/.ssh/config
Host github.com
  HostName ssh.github.com
  Port 443
```

**预防 / 经验**

- 超时和拒绝是两类问题：`refused` = 端口没开，`timed out` = 链路被掐
- 探端口用 `telnet 主机 端口` 或 `nc -zv 主机 端口`
- 大厂/开源项目一般都有备用通道（443、80），先查文档再折腾网络

**面试怎么说（30 秒）**

> 我用 SSH 连 GitHub 时一直超时，但 curl 网页是通的，说明不是断网，是端口层面的问题。SSH 默认走 22，22 被链路阻断就会这样。GitHub 官方提供了 443 的备用通道，我用 -p 443 连 ssh.github.com 验证通过，然后把它写进 ssh config，对 git 命令就透明了。

## C002　ssh 配置文件写了不生效

**现象**

按文档写了 `~/.ssh/config`，但 `ssh -T git@github.com` 仍然走 22、仍然超时。

**排查过程**

1. `ls -la ~/.ssh/` 发现文件叫 `config.txt`，不是 `config`
2. 原因：Windows 记事本保存时自动补 `.txt` 后缀
3. 改名后重测，走 443 正常

**根因**

ssh 只读取固定文件名 `~/.ssh/config`，带后缀的文件不解析；Windows 默认隐藏已知扩展名，容易看不出来。

**修法**

```
cd $env:USERPROFILE\.ssh
Rename-Item config.txt config
```

**预防 / 经验**

- Windows 上改配置文件，先关掉"隐藏已知文件类型的扩展名"
- 改任何配置后都要验证生效，不能假设"写了就等于生效"

## C003　建仓库报错，其实已经创建成功

**现象**

GitHub 点 Create repository，页面弹红色 `Something went wrong!`；刷新重试后提示：

```
ops-notes already exists in this account
```

**排查过程**

1. 第一次以为失败，直接重试
2. 提示"已存在"，说明第一次其实成功了
3. 去仓库列表确认，仓库确实在

**根因**

请求已送达服务端并写入成功，返回响应时链路出问题，前端只能显示失败。服务端的行为是成功的。

**修法**

不用修，先去确认状态。后续操作前先查（`git ls-remote`、列表页）。

**预防 / 经验**

- 分布式系统里"超时 ≠ 失败"，重试前先查状态
- 写自动化脚本时注意幂等：先查后改，避免重复创建/重复执行
