# 2026-11-24 · D2

昨天配好了密钥和仓库，今天要真正把 git 用一遍。计划写得很简单：add / commit / push / log / diff 走一遍，把攒的笔记放进仓库，写个 .gitignore。我以为是半小时的事，结果从 19:15 弄到 20:40，中间卡了两次，而且两次都是自己给自己挖的坑。

先补昨天的欠账。昨天发现电脑上只有便携版 git、开始菜单搜不到，今天决定装个正式的。官网 git-scm.com 太慢，换清华镜像下安装包，几十秒下完。装的时候没点 Next 一步步走，直接用了静默安装参数 `/VERYSILENT /NORESTART`——装完不弹窗、不要求重启，这种 Inno Setup 打包的 Windows 软件都吃这套参数。装完 Git Bash 终于能在开始菜单搜到了。

顺手把昨天那个 `config.txt` 改回 `config`：

```
cd $env:USERPROFILE\.ssh
Rename-Item config.txt config
ssh -T git@github.com
```

这次连接地址显示的是 `[ssh.github.com]:443`，说明 config 生效了（昨天还是 github.com:22）。中间又弹了一次 `Are you sure you want to continue connecting`，这回是我自己敲的 yes，后面跟着一行 `Permanently added ... to the list of known_hosts`——昨天查机制时只当是理论，今天算是看着它实打实写了一次。

进 Git Bash 配完身份，到 clone 这步我做了个自以为聪明的决定：不重新 clone 了，直接用昨晚就已经拉好的 `~/ops-notes` 目录，省一步。当时还挺得意，完全没意识到这个目录是昨晚拉的，昨晚之后仓库里又有新提交——这个"省一步"成了晚上 push 被拒的根源。

建今日文件的时候撞了今天第一个真坑。执行 `echo "# 11月24日" > notes/2026-11-24.md`，回车，什么都没发生，直接回到提示符。我以为没建成，去文件夹里翻也没看出变化。后来才明白这是 Linux 的老规矩：**成功不吭声，出错才说话**。验证不能靠肉眼等回显，得靠命令去问：

```
ls notes/                 # 文件在
cat notes/2026-11-24.md   # 内容对
git status                # 红色 untracked: notes/2026-11-24.md
```

看到那行红色 untracked 才算真正确认：文件建好了，git 看见它了，但还没跟踪。这条"验证靠命令不靠肉眼"比今天学的六个命令都值钱——以前我盯着屏幕等回显，现在知道该敲什么去主动确认。顺带把 shell 的重定向也用上了：`>` 覆盖、`>>` 追加。

add、commit 都顺利，到 push 直接红字：

```
! [rejected]  main -> main (fetch first)
error: failed to push some refs
hint: Updates were rejected because the remote contains work that you do not have locally.
```

第一次我没细看 hint，直接又 push 了一次，还是同样的报错。停下来把那句英文读完才明白：远端有我本地没有的提交。原因就是晚上那个"省一步"——我用的旧目录里没有昨晚之后推上去的内容。还有个我之前完全没意识到的坑：我中间在 GitHub 网页上改过 README、做过一次 `Add notes for Git commands` 的提交、还把 `2026-11-24.md` 删了重建，当时只当是"在网页上编辑文件"，没意识到网页上点一次 Commit changes 就是往远端提交一次，本地完全不知情。两件事叠一起，远端被我自己推前了。

解决就是三步：先 `git pull --rebase` 同步，再 `git log --oneline` 看清多出来的是什么，最后 `git push` 就过了。`pull --rebase` 的意思是把远端的新提交拉下来，再把我本地的提交"搬家"到它们后面，历史保持一条直线；不加 `--rebase` 会多出一条 `Merge branch...` 的合并记录，看着乱。弄懂这一层的感受是：push 被拒不是坏事，是 git 在拦着我别覆盖别人的东西。以后规律很简单，先 pull 再 push。顺带立了个规矩——改文件只在本地改，改完 add/commit/push，网页编辑只用于应急，用完记得本地 pull。

今天把 git 的四层结构在脑子里搭起来了：工作区（我在编辑的文件）→ 暂存区（add 之后）→ 本地仓库（commit 之后）→ 远端（push 之后）。add 不是"保存"是"挑选"——一个仓库改了五个文件，可以只挑两个进下一次存档；commit 只存在自己电脑上，push 完才有云端备份。以前觉得 add 和 commit 重复，现在知道它们中间隔着一道"挑拣"。还顺手记了 commit 说明的行业写法 `类型: 说明`，比如 `notes:`、`fix:`——这些东西以后面试官会翻，写清楚比写多重要。另外发现命令都有个通用结构：工具 → 选项 → 操作对象，`chmod -R 755 目录`、`git commit -m "说明"` 都是这个骨架，看清空格位置，遇到陌生命令能猜出一半。

欠着的：`git diff` 今天只看了说明还没真跑一遍，明天补；分支、合并、回滚完全没碰，明天说；网页误操作留下的两个 `Update README.md` 提交还在历史里，不影响用，但提交说明以后得写清楚。本地仓库现在比远端落后，明天开工先 pull。
