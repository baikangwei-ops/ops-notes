# 11月27日 · 故障日记（D5）

今晚的实验任务是快照、换系统、回滚、释放。这些操作本身没太多可写的，真正值得记的是中间撞到的三个跟"盘"有关的坑——每个都是先撞上，然后想歪，折腾一圈才摸到真相。就按这个顺序写。

## 一、开工 pull，GitHub 把我 reset 了

**怎么遇到的**：按收工口诀先 `git pull --rebase`，报 `Connection reset by 20.205.243.160 port 443`。

**我当时怎么想的**：第一反应是 D1 配的 443 通道坏了，手都伸向 ssh config 了，差点动手改。

**怎么试的**：停了一下再看报错——`20.205.243.160` 就是 GitHub 走 443 的服务器地址。能看到这个 IP、连的是 443，说明配置正在工作，问题不在配置。

**怎么解决的**：没改任何东西，原样重试，第二次就 `Already up to date.`。前后不到两分钟。

**最后发现是什么原因**：网络波动，连接建到一半被掐断。顺带把三种"连不上"分清楚了——超时是包压根没到（C001），拒绝是到了对方不让进，reset 是连接建起来了中途被踹。这种干扰几十秒到几分钟自己好，真遇上了先重试、再用 `ssh -T` 测通道，别动配置。配置是对的，乱改反而把对的改坏。

## 二、换系统后，回滚按钮是灰的

**怎么遇到的**：换完系统 ssh 上去，数据按预期没了（镜像起来了，但 `/root/important-data` 不见了）。灾难现场成立，按剧本该快照出场救场——结果快照列表里"回滚云盘"那个按钮是灰的，点不动。

**我当时怎么想的**：先怀疑控制台抽风，或者快照没做完。翻来覆去看了几遍，没头绪。

**怎么试的**：盯着快照列表一行行看，目光落到云盘 ID 上——快照属于那块旧盘 `d-bp17d8...`，而换系统之后实例挂的是**另一串新 ID**。

**怎么解决的**：旧盘救不回当前机器了，就在新盘上重来一遍闭环——重建标记文件 → 给这块新盘重拍一个快照 → 这次不换系统，直接 `rm -rf` 删掉标记文件制造灾难 → 对新快照回滚 → `cat mark.txt`，那行字回来了。

**最后发现是什么原因**：我原以为"更换操作系统"是清空重装，其实它是**换了一块全新的系统盘，旧盘被释放**。快照绑的是盘，不是实例——旧盘都没了，回滚自然没有对象。所以换系统之前得想清楚：它会让旧盘上的所有快照对当前实例失效。

还有个进阶路线先记账上：旧快照其实没废，用它的"创建自定义镜像"做成镜像，再拿镜像换系统，旧盘那套状态（连 mark.txt 一起）就能以新盘形式回来。这是跨盘恢复的正解，留给周日验收日玩。

## 三、密码那点事，我自己绕晕了自己

**怎么遇到的**：回滚前有人提醒"回滚后密码会退回拍快照那一刻的旧密码，先用旧密码试"。我照着试了好几次原来的密码，全登不上。

**我当时怎么想的**：以为回滚真把密码"时光倒流"了，于是更起劲地试旧密码，越试越懵。

**怎么试的**：卡了一会儿，干脆不想密码本身，改想"密码到底存在哪"——Linux 密码存在系统盘的 `/etc/shadow` 里，一串哈希。回滚是整块盘退回快照那一刻，shadow 也跟着退。可我这次是**同盘回滚**，盘从头到尾没换过，shadow 根本没动过。

**怎么解决的**：用那个"一直没变"的密码直接就登上了，根本没有"切换密码"这回事。

**最后发现是什么原因**：我把两组实验混了——换系统那次盘换了、密码跟着新盘变；这次同盘回滚、盘没换、密码也没变。我拿着前一次的结论去套后一次，能不晕吗。钉死一句：**密码跟盘走，不跟实例走，也不跟快照走。** 顺带把两个老问题一起解决了：控制台"重置密码"为什么要重启生效——因为重置是去改盘上的 shadow，sshd 要重启才重新读；为什么不能把别的盘的 shadow 直接搬过来——哈希带各盘自己的盐，搬过去也对不上。

## 今天这几个坑的共同点

三个坑的入口都不一样（网络、存储、认证），但卡住我的地方是同一类：**我拿着本地的老经验往云上套，套不通才逼着去想底层到底是什么**。git 配置、格式化重装、密码存在"某个后台"——这些想当然都是错的，真相都得落到"它物理上存在哪、跟着什么走"才能解释清楚。

> 今天最该记住的不是那几个结论（结论案例库里有），是那个卡住又拐过来的过程。下次再遇到"我以为它会这样，结果不是"，先别急着试，先问一句：这东西到底存在哪？
