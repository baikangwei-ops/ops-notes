# 11月27日 · 快照、换系统与回滚：一台服务器的“死而复生”（D5）

昨天给服务器“接生”，今天给它“重生”和“送终”。计划里 D5 只有一行：创建快照 → 换系统 → 从快照回滚 → 练习释放。我以为就是点几下按钮，结果这一天连撞三个跟“盘”有关的东西，最后自己把密码那层窗户纸捅破了。

今晚实际成果：**完整走通快照 → 灾难 → 复活**，外加两个控制台机制的真机发现（换系统=换盘、密码跟盘走），新增三条故障案例（C008 / C009 / C010）。

## 今日新掌握的操作

今天几乎没有新 Linux 命令，重心在**控制台操作路径**——找不到入口就等于不会，所以入口也要记。

| 操作 | 在哪 | 关键点 |
|---|---|---|
| 创建快照 | 实例详情 → 存储与快照 → 云盘那行 → 创建快照 | 快照的单位是**盘**不是机器；进行中不能停止/重启实例 |
| 更换操作系统 | 实例 → 更多 → 系统设置相关 → 更换操作系统 | **等于换一块新盘**，旧盘被释放（今天最大的坑） |
| 回滚云盘 | 快照列表 → 目标快照 → 操作列“回滚云盘” | 只能回滚到**还在的那块盘**；源盘没了按钮就灰 |
| 停止实例 | 实例列表 → 停止 | 有“强制停止/停止”和“普通/节省停机”两组开关，见下面 |
| 释放实例 | 更多 → 实例状态 → 释放设置 → 立即释放 | 昨天欠的练习，今天开局就补了 |

命令方面只有建标记文件的三连：

```bash
mkdir -p /root/important-data              # -p：父目录一起建，已存在也不报错
echo "快照回滚标记" > /root/important-data/mark.txt
cat /root/important-data/mark.txt           # 确认标记在（回滚后靠它验证成功）
rm -rf /root/important-data                 # 模拟灾难——今天唯一允许碰 rm -rf 的地方
```

## 19:11 开工先 pull，GitHub 把我 reset 了

按昨天的收工口诀开工先 `git pull --rebase`，结果报：

```
Connection reset by 20.205.243.160 port 443
fatal: Could not read from remote repository
```

第一反应是“我 D1 配的 443 通道坏了”。但转念一想：`20.205.243.160` 正是 GitHub 走 443 的地址——**说明配置在工作，只是连接中途被掐断**。

这里把三种“连不上”分清楚了（面试高频）：

| 报错 | 含义 | 我是谁 |
|---|---|---|
| `Connection timed out` | 包根本没到，链路不通 | C001（22 端口被墙） |
| `Connection refused` | 到了，但对方关门 | 理论款 |
| **`Connection reset`** | **通道建了一半被中间设备掐断** | ← 今天这个 |

结论是临时网络干扰，不是配置错。原样重试两次，第二次直接 `Already up to date.`——前后不到两分钟自己好了。记成 C008。

> `Already up to date` 不是失败也不是没反应，是 pull 的正常回答之一：远端没有比我更新的提交。

## 19:15 旧机送终、新机开局

按计划先把昨天那台北京实例**释放**了（昨天欠的练习，今天开局补上）——列表里实例消失，已用额度停止跳动，“停止≠释放”的实物课。

然后新开一台。开完才发现一个细节：**新实例落在“华东1（杭州）”，不是昨天那台北京**。地域变了，意味着以后想跟这台机器做内网互通，第二台也得选杭州。这条记进台账。

新机器的安全组得重新配（规则不跟着实例走）：允许 / 自定义 TCP / 22/22 / 源 0.0.0.0/0 / 描述“ssh 远程登录”。提交时弹出黄色风险提示——“全网开放 22 端口会被扫描器探测”。想了想点了“我已知悉并继续”：练习机用强密码、无敏感数据，被扫到无非日志多几条爆破记录；**生产环境这条提示就是真警告**，正确做法是源 IP 限定成公司出口、或干脆禁用密码只留密钥（D6 的课）。

## 19:25 拍快照：给后悔药上弦

先造一个“数据存在”的锚点：`/root/important-data/mark.txt`，写好确认在。然后控制台 → 存储与快照 → 云盘那行 → 创建快照，命名 `d5-练习前-20261127`。

三个细节：

1. **快照的单位是盘，不是机器**。页面让我选“云盘 / 实例”，选了云盘——快照就是一块盘在某个时刻的完整照片。（“实例”那个选项是一次性给多块盘拍一致性组，数据库多盘场景才用。）
2. **永久保留要计费**：快照按存储量从 300 额度里扣，40G 盘的首个快照大概每天几毛钱额度。所以快照和实例一样，是**用完要清的资源**——寒假前记得清理快照列表。
3. 进度条跑的时候顶部黄条警告“不要停止/重启实例”。我盯着进度条从 0 到 100%，**掐表记了耗时**（三个耗时数字的第一个）。

（小插曲：我给快照命名时把日期写成了 `202611.27`，中间多个点。不用改，但这正是“台账要检查”的现实例子。）

## 19:30 换系统：这一页藏着三个知识点

快照 100% 后进入“更换操作系统”页，这里连着撞了三样东西：

**① 安全设置默认停在“密钥对”**——密钥对是 D6 的正课，今晚不用它，切到“自定义密码”设了新密码。记住：**换系统会重置登录凭证**。

**② 取消勾选“免费安全加固”**——它要在机器上装常驻安全 agent。和昨天关掉营销弹窗同一个原则：学习机保持干净，软件自己手动装。（生产环境反而真会装这类主机安全产品，这是以后聊“主机安全基线”的素材。）

**③ 顶部有一条灰色 EOL 提示**：“CentOS 已于 2024 年 6 月 30 日全部停服，请尽早制定应对方案”。前几天我还担心“学了老版本怎么办”——**阿里云自己在页面上提示了这件事**。截图存证，这就是版本意识的现成素材。

页面还写系统盘是 `/dev/xvda`，但我昨天登进去 `lsblk` 看到的是 `vda`——**控制台文案是老模板，以机器里实际的为准**。这个原则以后到处用得上。

接着“停止实例”页又是一组选择：

- 停止方式：默认勾了“**强制停止**”（=直接断电，可能丢数据）。改成“停止”（=优雅结束进程、落盘）。强制停止是死机时的最后手段，正常关机永远先走“停止”。
- 停止模式：保持“**普通停机模式**”不动——蓝字明说“换系统请用普通模式，避免启动失败”。

这里把昨天那句“停止≠释放”又补了一层：**按量付费有两种“停”**——普通停机（CPU/内存继续收费，盘和公网 IP 也收费）和节省停机（计算资源停收，但盘照收、可能因为库存不足启动失败、公网 IP 可能变）。所以“停止还扣钱”更准确的说法是：**默认停机仍收算力钱，除非主动选节省停机**。

## 19:36 灾难现场，然后发现后悔药失灵

换完系统 ssh 重连，跑 `ls /root/important-data`：

```
ls: cannot access '/root/important-data': No such file or directory
```

数据没了——灾难模拟成立。按剧本，下一步该回滚快照救回来。

**结果回滚按钮是灰的。**

对着快照列表看了半天才反应过来——看云盘 ID：快照属于那块旧盘 `d-bp17d8...`，而换系统之后挂的是**另一块新盘**。快照绑的是盘，源盘被换系统释放了，回滚就没有对象了。

**我原以为换系统是“清空重装”，其实它直接换了一块全新的系统盘。** 这是今天最值钱的一条，记成 C009。

## 19:45 补救：在同一块盘上把闭环跑完

盘没了救不回当前机器，但盘还在的机制没坏。当晚重来一遍闭环：

1. 在新盘上重建标记文件 `mark.txt`
2. **在这块新盘上再拍一个快照** `d5-同盘回滚实验-20261127`
3. 等 100% 后，直接在机器里 `rm -rf /root/important-data` 模拟灾难（这次不用换系统了）
4. 停止实例 → 对新快照点“回滚云盘” → 启动 → 重连 → `cat mark.txt`

那行字回来了——**数据复活，回滚闭环成立**。三个耗时数字记全。

这一趟下来我意外集齐了**两组对照**：换系统灾难（盘换了，快照救不回当前实例）vs 删除灾难（盘还在，快照直接回滚）。这就是 C009 里“快照绑盘不绑实例”的实证。

还有一条进阶路线留给周末验收日：旧快照其实没废——用它的“创建自定义镜像”做成镜像，再用镜像去换系统，旧盘的完整状态（包括 mark.txt）会以新盘形式回来。这是“快照可以做成镜像”那句话的实操版，也是跨盘灾难恢复的正解。今天时间盒有限，先记账。

## 20:00 密码疑云：我原以为它会“时光倒流”，其实它一直跟着盘

回滚前收到提醒：“回滚后密码会变回拍快照那一刻的旧密码，先用旧密码试。”我照着试了好几次原来的密码，都登不进，卡了一会儿才反应过来——**密码根本没变**。

想通之后是这样：

- Linux 的密码不是存在云平台的后台，是存在系统盘的 `/etc/shadow` 文件里（一串加密哈希）
- **回滚 = 整块盘退回快照那一刻 = shadow 文件也退回那一刻 = 能登的密码就是那一刻的密码**
- 这次是**同盘回滚**，盘从头到尾没换过，shadow 文件根本没动过，所以前后是同一个密码，看起来“什么都没发生”

所以两次实验里密码的命运完全不同，我一开始把它们混了：

| | 第一次（换系统） | 第二次（rm + 同盘回滚） |
|---|---|---|
| 盘 | 换了 | 没换 |
| 密码 | 跟着新盘变 | 前后同一个 |

结论一句话：**密码跟盘走，不跟实例走、也不跟快照走。** 记成 C010。

延伸出两个以后肯定用得上的点：

- **控制台“重置密码”为什么必须重启生效？** 因为重置的本质是阿里云替你改那块盘上的 shadow 文件，sshd 要重启才重新读它
- **为什么不能把别的盘的 shadow 文件直接搬过来？** 密码哈希带各盘自己的盐，搬过去也对不上

> 这次是我拿着提醒去试，试不通反而逼出了底层模型。教训：**别把结论当圣旨，拿事实验证结论**——这次“验证失败”比“一次就对”学到的多得多。

## 今天弄明白的概念

**快照 vs 镜像**：快照是盘某时刻的数据副本（救数据）；镜像是整机系统环境的模板（批量复制服务器）。快照能做成镜像，镜像能基于快照生成。再深一层——只靠同地域快照不够，机房级故障（火灾、断电）会一起完蛋，生产备份要异地多副本 + 数据库另有 binlog。

**换系统 = 换盘**：这是今天推翻的旧认知。后果是旧盘释放、快照失去回滚对象、登录凭证重置。以后看到“更换操作系统”五个字，脑子里直接翻译成“换一块新盘”。

**密码跟盘走**：见上面。它把“重置密码要重启”“跨盘搬 shadow 不生效”一串问题都解释了。

**强制停止 vs 停止 / 普通停机 vs 节省停机**：两组开关对应两种维度——前者是“怎么断电”（优雅 vs 硬断），后者是“停了之后怎么计费”（算力照收 vs 停收但可能启动失败）。

**reset / timeout / refused 三兄弟**：见 C008 的对照表。
