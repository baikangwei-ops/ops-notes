# 11月27日 晚上 · 今天跟一块盘较劲了一晚上

昨天刚把第一台云服务器接生出来，今天就给它办了场葬礼，又办了场复活。计划上 D5 写着一行字：拍快照、换系统、回滚、释放。我本来以为就是点几下鼠标的活儿，结果一晚上撞了三个跟"盘"有关的东西，最后一个比一个有意思。

## 开工先把 GitHub 敲了一顿

收工口诀是"先 pull 再干活"，我就照着敲了 `git pull --rebase`，结果报：

```
Connection reset by 20.205.243.160 port 443
```

我当时第一反应是完了，D1 配的 443 通道是不是坏了，手都伸向 ssh config 了。停了一下想想不对——报错里那个 IP 就是 GitHub 走 443 的地址，能看到这个 IP、连的是 443，说明配置明明在工作，只是连到一半被掐断了。

这时候才把三种"连不上"分清楚：超时是包压根没到；拒绝是到了人家不给进；reset 是连接建起来了、中途被踹了。今天这个是第三种。我没改任何东西，原样重试，第二次就 `Already up to date.` 了。前后不到两分钟。记成 C008。

后来想想差点犯的错挺典型：网络一抖就想改配置。其实配置没错，乱改反倒把对的东西改坏了。

## 送走老的，开个新的

按计划先把昨天那台北京机器释放了。昨天只敢练到"停止"，今天补上"释放"——列表里实例真的消失了，额度也不跳了。这俩的区别昨天只写在纸上，今天算亲手摸到了。

然后开新机器。开完才注意到一件小事：它落在杭州，不是北京。地域这东西平时没感觉，等以后想让两台机器走内网互通时才发现——必须同一个地域、同一个 VPC。先记着。

新机器的安全组得重新配一遍，规则不会跟着实例走。还是那套：允许 / 自定义 TCP / 22/22 / 源 0.0.0.0/0。提交的时候弹了个黄色警告，说把 22 对全世界开着会被扫描器扫。我想了想点了"我已知悉"——练习机而已，密码够强、里面没东西，被扫到也就是日志里多几条爆破记录。但这条警告在生产环境是真警告，正确做法是把来源锁成公司出口 IP，或者干脆禁掉密码登录只留密钥，那是 D6 的事了。

## 拍快照：先造个"证据"

快照之前得先有点数据，不然回滚成没成功我根本看不出来。于是登上机器建了个标记文件：

```bash
mkdir -p /root/important-data
echo "快照回滚标记" > /root/important-data/mark.txt
cat /root/important-data/mark.txt
```

`mkdir -p` 这个 `-p` 挺好用——父目录一起建，目录已经在也不报错，写脚本的时候省事。

然后控制台 → 存储与快照 → 云盘那行 → 创建快照，起名 `d5-练习前-20261127`。这里有个细节我盯了一下：它让我选"云盘"还是"实例"，我选的云盘。快照的单位就是盘，一块盘某个时刻的完整照片。选"实例"那个是一次性给好几块盘拍一致性组，数据库多盘才用得上，跟我没关系。

页面还提醒快照进行中别停止重启实例。我就盯着进度条从 0 爬到 100%，掐了个表——这是今晚要记的三个耗时数字的头一个。

顺带发现快照是**按存储量计费**的，从那 300 额度里扣。所以它也跟实例一样，是"用完得清掉"的东西。我给它起名的时候还手滑把日期写成了 `202611.27`，中间多个点。懒得改了，但这事本身就说明台账得回头检查——写错一点点，以后找起来就费劲。

## 换系统那一页，藏了四样东西

快照拍完，进"更换操作系统"。这一页我前后看了好几遍，因为有四个东西需要动脑子。

一是安全设置默认停在"密钥对"上。那是 D6 的正课，今晚用不上，我切到"自定义密码"设了个新的。记住一条：换系统会重置登录凭证。

二是默认勾了个"免费安全加固"，要在机器上装常驻安全 agent。跟昨天关掉那个营销弹窗一个道理——学习机保持干净，软件自己手动装才有学习价值。生产环境倒是真装这类东西，那是后话。

三是页面顶上一条灰色提示："CentOS 已于 2024 年 6 月 30 日全部停服，请尽早制定应对方案"。前几天我还在担心学了老版本会不会面试被嫌弃——好家伙，阿里云自己都在页面上挂着这句话了。截图存下来，这以后就是"版本意识"的现成证据。

四是它把系统盘写成 `/dev/xvda`，可我昨天登进去 `lsblk` 看到的是 `vda`。控制台是老模板文案，机器里那个才是真的。以后这种"控制台说的和机器里实际的不一样"，一律以机器为准。

接着是"停止实例"页，又有两组开关。第一组默认勾的是"强制停止"——那是硬断电，可能丢数据。我改成普通的"停止"，让系统优雅地收尾。强制停止是死机时的最后手段，正常关机永远先走这个。第二组"停止模式"保持"普通停机"没动，蓝字明说了换系统要用普通模式，不然可能启动失败。

这里还把昨天那句"停止≠释放"补了一层：按量付费其实有两种停法。普通停机，CPU 内存照收钱；节省停机，算力不收了但盘还收，而且可能因为库存不够启动不起来、公网 IP 也可能变。所以"停止还扣钱"严格讲是"默认停机照样收算力钱，除非你自己选节省停机"。

## 数据没了，后悔药却失灵了

换完系统重新 ssh 上去，跑 `ls /root/important-data`：

```
ls: cannot access '/root/important-data': No such file or directory
```

没了。灾难现场成立，按剧本该轮到快照出场了。

结果——回滚按钮是灰的。

我盯着快照列表看了好一会儿，一开始还以为是控制台抽风、快照没做完。后来目光落到云盘 ID 上才反应过来：这个快照属于那块旧盘 `d-bp17d8...`，换系统之后实例挂的是**另一块新盘**。快照绑的是盘，旧盘被换系统释放了，回滚自然没有对象。

**我原以为换系统是"清空重装"，其实它直接换了一块全新的系统盘。** 这是今天最值钱的一条，C009。

## 那就重来一遍，在同一块盘上

盘没了救不回当前机器，但机制本身没坏。我重来了一轮闭环：

1. 在新盘上重建标记文件
2. 给这块新盘**重新拍一个快照** `d5-同盘回滚实验-20261127`
3. 等它 100% 后，这次不换系统了，直接在机器里 `rm -rf /root/important-data` 制造灾难（这是今天唯一一次允许自己碰 rm -rf，而且只许删这个目录）
4. 停止实例 → 对新快照点回滚 → 启动 → 重连 → `cat mark.txt`

那行字回来了。回滚闭环成立，三个耗时数字也凑齐了。

这么一折腾，我反倒白捡了两组对照：换系统那种灾难，盘换了、快照救不回当前实例；删除那种灾难，盘还在、快照直接回滚。C009 那句"快照绑盘不绑实例"，这下是真刻进去了。

还有条进阶路线我先记账上：旧快照其实没废，用它的"创建自定义镜像"做成镜像，再拿镜像去换系统，旧盘那套完整状态（包括 mark.txt）就能以新盘形式回来。这是"快照可以做成镜像"那句话的实操版，也是跨盘恢复的正解。今晚时间不够了，留到周日验收日玩。

## 密码那点事，我自己绕晕了自己

回滚之前有人提醒我"回滚后密码会退回拍快照时的旧密码，先用旧密码试"。我照着试了好几次原来的密码，全登不上，卡了一会儿才反应过来——密码根本没变。

想通以后是这么回事：

Linux 的密码不是存在云平台后台，是存在系统盘的 `/etc/shadow` 里，一串加密哈希。回滚就是整块盘退回快照那一刻，shadow 文件也跟着退回去，所以能登的密码就是那一刻的密码。可我这次是**同盘回滚**，盘从头到尾没换过，shadow 文件动都没动过，前后当然同一个密码——看起来就像"什么都没发生"。

坏就坏在我把两组实验混了。换系统那次盘换了、密码跟着变；这次盘没换、密码没变。我拿着前一次的结论去套后一次，能不晕吗。记成 C010。

一句话钉死：**密码跟盘走，不跟实例走，也不跟快照走。**

顺带把两个一直没想通的问题一起解决了：

- 控制台"重置密码"为什么要重启才生效？因为重置的本质是阿里云替你改盘上的 shadow，sshd 得重启才重新读一遍
- 为什么不能把别的盘的 shadow 直接搬过来？哈希带各盘自己的盐，搬过去也对不上

> 今天最该记住的其实不是这些结论，是那个过程：我拿着提醒去试，试不通，反而逼出了底层模型。别把别人的结论当圣旨，拿事实验证它——验证失败那一下学到的，比一次就对多得多。

## 今天弄明白的几个东西

**快照和镜像不是一回事**：快照是盘在某个时刻的数据副本，拿来救数据；镜像是整机环境的模板，拿来批量复制服务器。快照能做成镜像，镜像能基于快照生成。再想深一层，光靠同地域快照还不够——机房真着火了，快照和原盘一起完蛋，所以生产备份讲异地多副本、数据库另有 binlog。

**换系统=换盘**：今天推翻的旧认知。后果一串：旧盘释放、旧盘上的快照对当前实例失效、登录凭证重置。以后看到"更换操作系统"五个字，脑子里直接翻译成"换一块新盘"。

**密码跟盘走**：上面那一段。它把"重置密码要重启""跨盘 shadow 搬不过来"一串问题都解释了。

**reset / timeout / refused 三兄弟**：见 C008 那张对照。
